05

Inside stage 4 “analyze” — 11 sub-steps

This is where the landscape is actually created. Each box is timed and its backend recorded in meta.json.

  1. index — build NeighborIndex Exact chunked inner product under 20k papers; FAISS IndexHNSWFlat above. ANN recall@25 is measured against exact search on a sample and stored in the validation report.
  2. reduce — embeddings → 8 dimensions UMAP (n_neighbors 15, min_dist 0.0), PCA fallback. Fitted on a 60k sample for huge corpora, the rest transformed.
  3. cluster — density clustering on the 8-d space HDBSCAN (leaf selection) → DBSCAN with k-distance eps → KMeans, in that order of preference. Noise is kept as cluster -1, never forced into a group.
  4. match previous — stable area IDs Hungarian assignment on Jaccard member overlap + centroid similarity against the last release. Matched areas inherit their old ID; merges and splits land in the user changelog.
  5. stability — subsample re-clustering Re-clusters under seeds [0,1,2], reports mean ARI and per-cluster survival. ARI is a required publish gate.
  6. label — c-TF-IDF names + evidence Class-based TF-IDF over cluster-aggregated documents (BERTopic formulation) gives 8 keywords; the 5 papers nearest the cluster centroid are kept as visible justification.
  7. project — a separate 2-d map A second UMAP run used only for visualisation (min_dist 0.1). The 2-d map is deliberately never the analytical basis.
  8. growth — who is accelerating Per area and window (3/6/12 months): recent/previous, divided by the same ratio for the whole corpus, weighted by sample_weight. Poisson bootstrap (500 samples, 90% CI), stability across alternate reference dates (CV ≤ 0.5), plus a window-free Poisson log-linear trend. No smoothing; gated areas simply report nothing.
  9. sparse — investigation leads Low-density 2-d anchors bordering populated clusters → re-verified in high-dimensional space → nearby papers attached as evidence → kept only if still low-density under a majority of re-projections. Capped at 12 leads, disabled below min_corpus_size.
  10. graph — the paper network k=6 nearest neighbours per paper via the shared index (no n×n matrix ever materialised), weight boosted by shared references (bibliographic coupling, +0.15 each, capped). Output: undirected edge list + per-paper neighbour list.
  11. bm25 · phrases · acronyms — lexical side BM25 term-frequency matrix with frequent bigrams; normalised phrase text for millisecond substring scans; acronym pairs mined from abstracts (“self-admitted technical debt (SATD)”) for two-way query expansion.

Measured every build

Cluster quality

  • silhouette · DBCV (sampled)
  • NPMI keyword coherence · keyword diversity

One search, end to end

This is the only hot path in the system — and the only place the app does ML.

  1. Clean & expand the query Trimmed to 300 chars, then expanded two ways with mined acronyms and configured synonyms: “SATD” ⟷ “self-admitted technical debt”. Two forms are produced — normalised phrases for local matching, and api_phrases for exact-phrase queries to external APIs.
  2. Embed the query — once Same Embedder the corpus was built with, plus the saved query_prefix. The vector is reused by every subsequent step.
  3. Search the local collection in-process Dense: cosine over all embeddings (full scan when small, otherwise the ANN index). Lexical: BM25 scores with the bigram bonus. Exact: phrase index returns a match level — 1 title, 2 abstract, 3 all content words within 8 words.
  4. Fan out to three external sources — in parallel network A thread pool hits arXiv, OpenAlex and Semantic Scholar at once. Hard deadline 10 s overall; Semantic Scholar gets 6 s and is dropped if slower; a source that answers 429 is put on a 60 s cooldown; every page is cached on disk for 24 h, so repeats and paging back are instant.
  5. De-duplicate across sources Identity by DOI, then arXiv ID, then normalised title + year (allowing a one-year preprint/publication gap). Records from different sources are merged field by field.
  6. Persist and embed the new papers Unseen papers are upserted into data/live/. Up to 300 of them are embedded within a 4 s budget; the rest get vectors on later searches. The collection grows with use.
  7. Rank into two honest sections Exact — ordered by match level, then by dense + lexical score. Related — dense and BM25 rankings fused by Reciprocal Rank Fusion, then cut by an adaptive threshold (mean + 2σ of the query’s similarity to the corpus, and halfway to the best match), so weak matches are dropped rather than padded.
  8. Post-process & report Optional citation boost and cross-encoder re-rank; sort by relevance / newest / most cited / citation velocity; attach matched terms, cluster distribution (query ambiguity is exposed), source status per API, totals, and the degraded flag.

Local vs online — the honest boundary

🖥 Runs locally / in-process
  • All clustering, reduction, labelling, growth statistics, lead detection
  • All embedding (model runs on your CPU/GPU, or the container’s)
  • All retrieval: dense, BM25, FAISS, phrase matching
  • All storage: Parquet, DuckDB, .npy, JSON — files on a disk
  • The whole app: Streamlit server + the React bundle it serves
│
🌐 Crosses the network
  • arXiv — search API (build) and OAI-PMH (refresh); also a live search source
  • OpenAlex — citations, references, venues, authors (build); also a live source
  • Semantic Scholar — live source + optional cross-check (needs a key)
  • Hugging Face — model download, once; baked into the image for production
  • Sentry — error reports, only if a DSN is set, no personal data

Not used: no managed database, no object storage, no queue, no third-party auth, no analytics.
