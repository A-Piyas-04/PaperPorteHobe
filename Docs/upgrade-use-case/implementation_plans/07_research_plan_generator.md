# Plan 07: Starter research plan generator (Gap Card → plan)

> **Prerequisites:** plans 01–06 are merged. Gap Cards exist (offline area cards and online workspace cards).
> **Produces:** `scholargrid/plan/`: collects **computed** context for a chosen gap (references, baselines with code, datasets, metrics, venues, active authors, reading list), asks the LLM (free Gemini tier, 1 request per plan) for a **grounded** `ResearchPlan` personalised to the user's background and time, verifies that named baselines and datasets come from the references, falls back to a template without an LLM, and exports Markdown, JSON and BibTeX. Adds the **Plan** page.
> **Why:** a beginner who has found a promising gap still asks "so what do I actually do on Monday?". This closes the journey.

## 2. What is computed vs generated

| Part of the plan | Source | Why |
|---|---|---|
| References R1..Rn (evidence + related + foundations) | **computed** | ground truth for the LLM |
| Candidate baselines (methods with role `proposed` in related papers, with code links) | **computed** list; LLM chooses and explains | names must be real |
| Datasets and metrics (facet counts among related papers) | **computed** list; LLM chooses and explains | same |
| Venues (OpenAlex `venue` counts among related papers) | **computed only** | factual |
| People (most frequent authors among related papers, with OpenAlex author links) | **computed only** | factual; for finding supervisors and collaborators |
| Research question, hypotheses, method sketch, experiments, milestones, risks, skills, supervisor questions | **generated** | creative, but bounded by references |

## 4. Schemas: `scholargrid/plan/schemas.py`

```python
"""ResearchPlan (LLM output) and PlanDocument (what is shown, saved and exported)."""
from __future__ import annotations

import time
from typing import Dict, List, Literal

from pydantic import BaseModel, Field, field_validator


def _clip(v, n):
    s = " ".join(str(v or "").split())
    return s[:n]


class Choice(BaseModel):
    name: str
    why: str
    ref: str               # "R3" - must be one of the provided reference ids

    @field_validator("name", "why", "ref", mode="before")
    @classmethod
    def _c(cls, v):
        return _clip(v, 240)


class Milestone(BaseModel):
    weeks: str             # e.g. "1-2"
    goal: str
    tasks: List[str]
    deliverable: str


class Risk(BaseModel):
    risk: str
    mitigation: str


class ResearchPlan(BaseModel):
    title: str
    research_question: str
    sub_questions: List[str]
    hypotheses: List[str]
    why_it_matters: str
    contribution_type: Literal["new_method", "empirical_study", "benchmark_or_dataset", "reproduction",
                               "system_or_tool", "analysis"]
    method_sketch: str
    baselines: List[Choice]
    datasets: List[Choice]
    metrics: List[str]
    experiments: List[str]
    minimum_viable_result: str
    stretch_goals: List[str]
    milestones: List[Milestone]
    risks: List[Risk]
    skills_to_learn: List[str]
    compute_estimate: str
    questions_for_supervisor: List[str]
    references_used: List[str]

    @field_validator("sub_questions", "hypotheses", "metrics", "experiments", "stretch_goals",
                     "skills_to_learn", "questions_for_supervisor", mode="before")
    @classmethod
    def _lists(cls, v):
        return [_clip(x, 300) for x in (v or [])][:8]

    @field_validator("milestones", mode="before")
    @classmethod
    def _ms(cls, v):
        return list(v or [])[:8]


class PlanDocument(BaseModel):
    id: str
    gap_id: str
    gap_snapshot: Dict                     # the GapCard as it was (model_dump)
    plan: ResearchPlan
    references: List[Dict]                 # [{rid, paper_id, title, year, url, role}]
    computed: Dict                         # venues, people, code_links, dataset_counts, metric_counts, reading
    inputs: Dict                           # weeks, background, compute_access, goal
    warnings: List[str] = Field(default_factory=list)
    generated_by: Dict = Field(default_factory=dict)   # {"model", "prompt_version", "mode": "llm"|"template"}
    created_at: float = Field(default_factory=time.time)
```

## 5. Context builder: `scholargrid/plan/context.py`

```python
def plan_context(card: GapCard, bundle, cfg, embedder, workspace=None) -> Dict:
    """
    references:
      R-ids first for card.evidence papers (keep their role),
      then `related_top` papers most similar to the statement vector among
        (workspace collection papers if given, else the card's area) excluding evidence,
      then `foundations_top` items from the workspace/area reading path (step foundation/survey).
      Cap at max_references. Each: rid, paper_id, title, year, url, role, summary (profiles.summary or
      first abstract sentence), methods (proposed), datasets, metrics, code_url.
    computed:
      dataset_counts / metric_counts / method_counts over referenced corpus papers (canonical facets),
      code_links: [{paper_id, title, code_url}] for referenced papers with code,
      venues: top `venues_top` non-empty df['venue'] values among related papers with counts,
      people: top `people_top` authors by number of related papers. Use df['authors'] (';'-separated
        names) aligned with df['author_ids'] (space-separated OpenAlex ids) when lengths match, giving
        links https://openalex.org/<A-id>; otherwise names only,
      reading: the reading-path items used.
    """
```

People and venues are computed **only** from the related set (≤ ~30 papers), and the UI says so: "Most frequent authors among the papers this plan builds on (not a ranking of researchers)."

## 6. Prompt: `scholargrid/plan/prompts.py`

```python
PLAN_SYSTEM = """You help an early-career researcher turn one research gap into a realistic starter project.
Work ONLY from the gap card and the numbered references [R#] provided. Rules:
1. Baselines and datasets must be chosen from the references' listed methods/datasets; give the [R#] in
   'ref'. If no suitable dataset is listed, say so in risks and propose how to obtain one.
2. Keep the scope achievable in the given number of weeks by ONE person with the stated background and
   compute. Prefer a reproduction + one clear extension over a grand new system.
3. minimum_viable_result: the smallest result that is still worth writing up.
4. milestones: cover exactly the given number of weeks, contiguous ranges ("1-2", "3-4", ...), each with
   a concrete deliverable (a working baseline, a results table, a draft section).
5. risks: include at least one risk that the gap is already addressed somewhere not checked, and how to
   check (search terms, venues to scan, asking a supervisor).
6. questions_for_supervisor: 3-5 specific questions that would help decide whether to pursue this.
7. Plain English. Explain jargon briefly the first time. No claims about novelty beyond the gap card's
   novelty check."""

register(Prompt(name="research_plan", version="1", system=PLAN_SYSTEM, user=(
    "Weeks available: $weeks\nGoal: $goal\nCompute access: $compute\n"
    "<user_background>\n$background\n</user_background>\n\n"
    "Gap card:\n$gap\n\n<evidence>\n$references\n</evidence>\n\n"
    "Computed facts (for your information; do not restate as your own claims):\n$computed")))
```

- `$gap`: title, statement, type, why_it_might_not_be_a_gap, first_steps, novelty status/date.
- `$references`: one block per reference: `[R3] (2024) Title | summary | methods: … | datasets: … | metrics: … | code: yes/no`.
- `$computed`: dataset/metric counts only (people/venues are not given to the LLM; they are displayed separately).
- Register a fake handler that returns a schema-valid plan built from the first references (milestones split by `$weeks`).

## 7. Generate, verify, fall back: `scholargrid/plan/generate.py`

```python
def generate_plan(card: GapCard, bundle, cfg, llm, embedder, *, weeks: int, background: str,
                  compute_access: str, goal: str, workspace=None) -> PlanDocument:
    ctx = plan_context(card, bundle, cfg, embedder, workspace)
    inputs = {"weeks": weeks, "background": background[: cfg["plan"]["max_background_chars"]],
              "compute_access": compute_access, "goal": goal}
    warnings: list[str] = []
    try:
        res = llm.structured("plan", "research_plan", ResearchPlan, weeks=weeks, goal=goal,
                             compute=compute_access, background=inputs["background"] or "not given",
                             gap=_gap_text(card), references=_refs_text(ctx["references"]),
                             computed=_computed_text(ctx["computed"]))
        plan, mode, model = res.value, "llm", res.model
        issues = verify_plan(plan, ctx, weeks)
        if issues:
            warnings += issues
            plan = repair_plan(plan, ctx, issues)     # drop unverifiable choices, fix week ranges
    except LLMError as exc:
        warnings.append(f"Plan written from a template ({type(exc).__name__}).")
        plan, mode, model = template_plan(card, ctx, weeks), "template", "none"
    return PlanDocument(id=..., gap_id=card.id, gap_snapshot=card.model_dump(), plan=plan,
                        references=ctx["references"], computed=ctx["computed"], inputs=inputs,
                        warnings=warnings, generated_by={"model": model, "mode": mode,
                                                         "prompt_version": PROMPTS["research_plan"].version})
```

**`verify_plan` checks:**
1. Every `Choice.ref` is an existing R-id.
2. Every baseline/dataset `name` appears (case-insensitive, `rapidfuzz.fuzz.partial_ratio ≥ 85`) in the referenced paper's methods/datasets/title/summary.
3. The milestones cover `1..weeks` with no gaps or overlaps (parse "a-b" ranges).
4. `references_used` ⊆ R-ids.
5. `gaps.verify.foreign_entities` on `research_question + method_sketch` against the references' text. These are warnings only (the plan may legitimately name general concepts).

**`repair_plan`:** removes unverifiable baselines/datasets and appends a risk "Dataset choice needs confirmation: none of the references lists a suitable dataset". If milestones are broken, it re-buckets them evenly over the weeks.

**`template_plan`** (no LLM): research question = the gap statement turned into a question; baselines = the top 2 methods with code from `computed`; datasets = the top 2 dataset counts; metrics = the top 2 metric counts; milestones = a standard sequence over `weeks` (read & reproduce → baseline → extension → experiments → write-up); risks = the gap card's `why_it_might_not_be_a_gap` items as risks; supervisor questions = 3 generic but useful ones.

## 8. Export: `scholargrid/plan/export.py`

- `plan_to_markdown(doc) -> str`: title, the gap (with its novelty status and date), research question, sub-questions, hypotheses, why it matters, method sketch, baselines/datasets tables (name, why, reference link), metrics, experiments, minimum viable result, stretch goals, milestones table, risks table, skills, compute, supervisor questions, **computed** sections (people, venues, code links) clearly headed "Computed from the referenced papers", references list with links, and a footer: "Generated by ScholarGrid on {date} ({mode}). Verify every reference before relying on it."
- `plan_to_json(doc) -> str`: `doc.model_dump_json(indent=2)`.
- `plan_to_bibtex(doc) -> str`: reuse `views.home._bibtex` logic. Move it to `scholargrid/bibtex.py` so both the app and the library can import it, and update `views/home.py` and `views/library.py` to import from there.
- `supervisor_email(doc) -> str`: a 120-word plain-text summary (gap, question, plan in 3 bullets, ask for a meeting), deterministic from the plan fields.

   - submit "Create my starter plan".
4. Generate under `st.status("Writing your plan… (about a minute)")`. Cache the result in session `plans[gap_id][inputs_hash]`.
5. **Render:** tabs "Plan", "Timeline", "Resources" and "Export".
   - **Plan:** question, hypotheses, method sketch, baselines/datasets with "why" and reference links, experiments, MVR, risks.
   - **Timeline:** milestones as a vertical list or a Plotly timeline with deliverables.
   - **Resources:** reading list (foundations), code links, people, venues; computed sections are labelled.

6. Warnings (template mode, repaired choices) shown as `ui.note`.
7. Buttons: "Save plan to project" (plan 08) and "Regenerate" (bypasses the session cache; the LLM disk cache still applies to identical inputs, so add an `attempt` variable to the prompt when the user explicitly regenerates).

## 12. Pitfalls

- The background text is user input: wrap it in `<user_background>` and cap its length. It is not an instruction channel.
- Don't pass people/venues to the LLM. They are facts to display, not material to embellish.
- Week parsing: accept "1-2", "1–2", "Week 1-2", "3". Normalize before verification.
- Plans are long. If `LLMTruncated` happens, raise `llm.tasks.plan.max_output_tokens` (thinking tokens count toward it) or lower `thinking` to `low`. Don't silently cut output.
- **Privacy on free tiers:** the background text is sent to the LLM provider, and free-tier content may be used to improve the provider's products. Show this under the background field: "This text is sent to Google Gemini (free tier). Don't include personal or confidential information." Leave it empty by default.
